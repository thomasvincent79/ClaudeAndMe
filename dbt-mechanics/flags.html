1 · Where can a flag be set? (highest priority first)

1

Command line

dbt build --fail-fast. It always wins and applies to this invocation only. Every flag exists here.

2

Environment variable

DBT_FAIL_FAST=true (prefix DBT_) DBT_ENGINE_FAIL_FAST=true (prefix DBT_ENGINE_ since 1.11). Ideal for CI runners and containers.

3

dbt_project.yml → flags:

Project-wide defaults for "behaviour" flags (fail_fast, warn_error, partial_parse…), committed with the code. Since 1.8 this replaces the old config: block in profiles.yml.

4

Resource config

A few flags have a per-model twin: full_refresh, store_failures. The config full_refresh: false even overrides --full-refresh.

5

dbt default

Used when nothing above is set.

1.8.6
dbt_project.yml
flags:
  fail_fast: true
  warn_error_options:
    include: [NoNodesForSelectionCriteria]   # 'include'/'exclude' in 1.8
  partial_parse: true
  send_anonymous_usage_stats: false
export DBT_FULL_REFRESH=true      # env var form
export DBT_TARGET=ci
1.12
dbt_project.yml
flags:
  fail_fast: true
  warn_error_options:
    error: [NoNodesForSelectionCriteria]     # renamed in 1.10
    silence: [Deprecations]
  # behaviour-change opt-ins live here too (only here):
  require_sql_header_in_test_configs: true
export DBT_ENGINE_FULL_REFRESH=true   # 1.11+ prefix
export DBT_ENGINE_TARGET=ci
# 1.12 also loads a .env file from the working directory
Not everything goes everywhere

Run-scoped flags (--select, --empty, --defer, --state, --sample, --event-time-*, --target) cannot go in flags:, because they describe one invocation, not the project. --select has no environment variable at all (use selectors.yml to version a selection). When migrating, check that old DBT_* env vars are still picked up, or rename them to DBT_ENGINE_*.

💻

Dev loop

dbt build -s fct_orders+ --defer --state prod/
dbt build -s fct_orders+ --sample="3 days"   # 1.10+

Build what you touched and its children. Read everything else from prod.

🧪

Slim CI

dbt build -s state:modified+ --defer --state prod/ --empty -x   # 1: schema check
dbt build -s state:modified+ --defer --state prod/ -x           # 2: real data

The first pass catches SQL and contract errors in seconds. The second runs the data tests.

🌙

Production nightly

dbt source freshness
dbt build --selector nightly --exclude-resource-type unit_test
dbt retry   # if it failed: resume at the failure

No --fail-fast: independent branches still deliver.

⏪

Backfill a period

dbt run -s fct_orders --vars '{"from": "2024-09-01"}'   # var used in is_incremental()dbt run -s fct_orders --event-time-start "2024-09-01" --event-time-end "2024-09-04"

Rebuild a window without a full refresh.

🔁

Logic change on an incremental

dbt build -s fct_orders+ --full-refresh

Rebuild the model and its children. Use the config full_refresh: false on models whose history can't be rebuilt.

🌱

Seed columns changed

dbt seed -s country_codes --full-refresh

A normal seed run truncates and inserts, so it can't change columns. This drops and recreates the table.
