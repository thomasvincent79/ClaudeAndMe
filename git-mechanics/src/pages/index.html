git vs GitLab in one picture

git is the tool (Linus Torvalds, 2005): it stores snapshots of your project and lets you branch and merge cheaply. GitLab (like GitHub or Bitbucket) is a platform built around git: it hosts the central copy everyone pushes to, and adds collaboration (merge requests, reviews) and automation (CI/CD). You can use git without GitLab; you cannot use GitLab without git.

Suggested path

1 · Local git

Basics → Branches → Undo. Enough to work alone with confidence.

2 · Team git

Remotes → GitLab workflow. Pushing, pulling, merge requests and reviews.

3 · Automation

CI/CD: every push runs your lint, tests and deploys, including a dbt slim-CI job.

How to regenerate the pages

Edit the sources in src/pages/*.html and src/js/*.js, then run python build.py (or python build.py --serve to also serve them on localhost:8820). To add a topic, add a fragment and one entry in THEMATICS in build.py.
