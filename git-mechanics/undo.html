⏪ Undoing things

Almost nothing is really lost

git has a different "undo" for each area: restore for files, reset to move a branch back, revert to undo safely on shared history, stash to put work aside, and the reflog to get back from (almost) any mistake. The only thing git can't give back is work you never staged or committed.

2 · reset --soft / --mixed / --hard

git reset <commit> always moves the current branch (and HEAD) to <commit>. The mode decides how far the reset goes into the other two areas:

ModeBranch / HEADStaging areaWorking directoryTypical use
--softmovedkeptkept"Uncommit": redo the last commit(s) differently, or squash them into one
--mixed (default)movedreset to the commitkeptUncommit and unstage, keep edits on disk to re-split them
--hardmovedreset to the commitoverwritten ⚠Throw everything away and match a commit exactly (e.g. reset --hard origin/main)
reset --hard deletes uncommitted work

Committed work can be found again in the reflog. Changes that were only in your working directory, never added or committed, are gone for good. Run git stash first if unsure.

3 · Which undo do I need?

SituationCommandRewrites history?
Discard my edits to a file (not staged)git restore app.pyno (but edits are lost)

Abort a merge or rebase in progressgit merge --abort / git rebase --abortrestores

Older docs use git checkout -- file for what git restore does. It still works, but restore / switch (git 2.23+) split checkout's two jobs and are harder to misuse.

4 · The reflog safety net

git reflog
e4f1a9c HEAD@{0}: reset: moving to HEAD~2
77c2e0a HEAD@{1}: commit: Add tests
4b9e211 HEAD@{2}: commit: Fix VAT rounding
a1d03f7 HEAD@{3}: checkout: moving from feature to main

# oops, I wanted those two commits back:
git reset --hard HEAD@{1}
# or keep them on a new branch:
git branch rescue 77c2e0a

Every time HEAD moves (commit, reset, rebase, switch, merge, pull), git appends a line to .git/logs/HEAD. Commits that no branch points to anymore are still there.

They're kept around ~30 days for unreachable entries (90 for reachable ones) before git gc may prune them. The reflog is local only: it's not pushed, and a fresh clone has none.

5 · Stash

git stash push -m "wip discount"  # save staged + unstaged, clean the tree
git stash -u                       # include untracked files too
git stash list                     # stash@{0}: On main: wip discount
git stash pop                      # re-apply the latest and drop it
git stash apply stash@{1}          # re-apply, keep it in the list
git stash branch fix-later         # new branch from the stash

A stash is a pocket for unfinished work, for example when you must switch branches to fix something urgent.

It's best for short interruptions. For anything longer, a real wip commit on a branch is easier to find, and gets pushed as a backup.
